### Fixes

- **`@liendev/lien@0.80.3` is broken and this replaces it.** That version fails on its very first import:

  ```text
  SyntaxError: The requested module '@liendev/parser' does not provide an export named 'LANGUAGE_IDS'
  ```

  `lien complexity` names the languages it can analyse in one of its no-data refusals, and 0.80.3 read that list from a `LANGUAGE_IDS` export newly added to `@liendev/parser`. The changeset for that release named only `@liendev/lien`, so the parser was never published with the export; the CLI resolved its declared `^0.80.2` and threw. Every command was affected, since the failure is at module load.

  The list now comes from `getAllLanguages()`, which `@liendev/parser` has exported since before 0.80.2, so it resolves against the range the CLI actually declares. `LANGUAGE_IDS` is internal again — it was never published, and not exporting it is the better call anyway: `SupportedLanguage` is `(typeof LANGUAGE_IDS)[number]`, so publishing the array would make removing or renaming an entry a breaking change.

  Verified the way the incident demands rather than in the workspace: packed the CLI, installed it into a workspace-free directory so `@liendev/parser` resolved from the registry (0.80.2), and confirmed both that it imports and that the refusal renders its language list.

  0.80.3 should be deprecated on npm; it cannot be unpublished.

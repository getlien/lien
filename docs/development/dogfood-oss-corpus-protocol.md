# Dogfood protocol: MCP tools + nudge plugin, on foreign repos

**Status:** plan, frozen before any trial runs. **Instrument:**
[`scripts/experiments/dogfood-oss/`](../../scripts/experiments/dogfood-oss/).

This is the pre-registration for an extensive dogfooding session over Lien's two
consumer surfaces:

1. the **six MCP tools** — `search_code`, `find_similar`, `get_files_context`,
   `list_functions`, `get_dependents`, `get_complexity`;
2. the **nudge plugin** — the ten hooks in `plugins/claude/hooks/`, their env kill
   switches, the habituation guard, and the `lien stats` funnels they feed.

It exists because the repo's own [dogfood mandate](../../CLAUDE.md) is satisfied
only by exercising a change the way its real consumer experiences it — and Lien's
real consumer is *an agent in somebody else's codebase*, not an agent in this one.

---

## 1. Why this cannot run inside the Lien repo

Lien's own `CLAUDE.md` contains a section titled **"Lien MCP Tools — MANDATORY
Usage"** which instructs any agent working here to call `get_files_context` before
editing, `get_dependents` before touching an exported symbol, and `search_code`
before grep. The plugin's value proposition is the *opposite* of that: it claims to
produce those behaviors in agents that were **never told** to do them.

Measuring nudge response inside this repo therefore measures the instructions, not
the nudge. Every behavioral observation in this protocol runs in a **cloned
third-party repository** with no Lien-aware agent instructions anywhere on the path.

This is the same contamination control the proven
[nudge A/B v2](nudge-ab-v2-protocol.md) uses (`assertNoAncestorClaudeMd`, ambient
plugin disabled per-process via `--settings`), extended from synthetic fixtures to
real code. Real repos are the upgrade: synthetic fixtures prove a nudge *can* change
behavior, foreign repos prove the nudge is *correct and useful* on code nobody
tuned it against.

### Contamination controls (all five are gates, not guidelines)

| # | Control | Enforcement |
|---|---|---|
| C1 | No `CLAUDE.md`, `AGENTS.md`, `.cursor/rules`, `.cursorrules`, `.github/copilot-instructions.md` in the clone or any ancestor dir up to `/` | Provisioner asserts; repo quarantined on failure |
| C2 | Ambient `lien@lien` plugin disabled for the spawned process only | Per-invocation `--settings` `enabledPlugins` override; saved `~/.claude/settings.json` byte-compared before/after |
| C3 | Hooks wired by absolute path, toggled only by their real env kill switches | `--settings` hook block generated by the runner |
| C4 | Task prompts never mention callers, dependents, tests, coverage, risk, complexity, or Lien | Prompts frozen in `prompts/`, hash recorded per trial |
| C5 | Repos pinned to SHAs; clone is `git init`-fresh so `lien delta` has a HEAD | Provisioner records SHA in every trial artifact |

C4 is the lesson from the v1 nulls: when the nudged behavior is derivable from the
task, both arms do it and there is no headroom to measure. Every task below is
**task-decoupled** by construction and that decoupling is asserted with zero LLM
spend before any session runs.

## 2. Corpus

Nine repos, nine languages. Split deliberately:

**Known-ground-truth** (swept in dogfood round 2, so dependency and
test-association ground truth is already established and re-verification is cheap):

| Repo | Language | License |
|---|---|---|
| `pallets/flask` | Python | BSD-3-Clause |
| `gin-gonic/gin` | Go | MIT |
| `tokio-rs/tokio` | Rust | MIT |
| `Alamofire/Alamofire` | Swift | MIT |

**Fresh** (never swept — guards against overfitting the extractors to the four
above):

| Repo | Language | License |
|---|---|---|
| `honojs/hono` | TypeScript | MIT |
| `square/retrofit` | Java | Apache-2.0 |
| `symfony/console` | PHP | MIT |
| `serilog/serilog` | C# | Apache-2.0 |
| `sidekiq/sidekiq` | Ruby | LGPL-3.0 |

**Selection criteria** (a repo that fails any is replaced, and the replacement is
recorded): passes C1; has a real test suite using its ecosystem's mainstream naming
convention; 200–3000 indexable source files; a license permitting local cloning and
analysis — nothing here is redistributed; pinned SHA.

### C1 has a real base rate — the quarantine gate is load-bearing

Screening candidates against the GitHub API on 2026-07-28 disqualified **three of
nine** first-choice repos for shipping their own agent instructions:

| Rejected | Language | Reason |
|---|---|---|
| `cli/cli` | Go | ships `AGENTS.md` |
| `guzzle/guzzle` | PHP | ships `AGENTS.md` **and** `CLAUDE.md` |
| `onevcat/Kingfisher` | Swift | ships `AGENTS.md` **and** `CLAUDE.md` |

`rubocop/rubocop`, screened as a Ruby candidate, ships both as well.

Two consequences worth internalizing. First, roughly a third of popular OSS repos now
carry agent-instruction files, so "clone a random repo" is **not** a contamination
control by itself — C1 has to be enforced mechanically. Second, the three rejects were
Go, PHP and Swift, three of the four languages whose test-association layer was
measured broken in the 2026-07-25 sweep. Dropping them would have quietly gutted the
most valuable part of this protocol, so each was *replaced in-language* rather than
removed.

The screen above was done at the API level against default branches. The provisioner
**must re-assert C1 against the pinned SHA at clone time** — a repo can add an
`AGENTS.md` between this screening and the run, and an ancestor directory can carry
one regardless of what the repo contains.

The language spread is not decoration. Memory of the 2026-07-25 language-coverage
sweep records that the test-association layer was **100% broken** on PHP, Go, Swift
and C# mainstream conventions (#866–#869), with fixes landing across #907/#909/#911/
#913/#914. Three of the nudges (`test-reminder`, `test-run-note`, the `recap-stop`
unrun-tests ledger) are built directly on test associations. If those fixes did not
hold, the nudges do not merely go quiet — **they assert something false**, which is
the single worst failure mode available to this product. Phase 4 exists to catch
exactly that.

## 3. Task design

Two tasks per repo, both ordinary-looking, both with verified nudge headroom.

**T1 — signature task (targets the blast-radius nudge).** Extend or change an
exported function that has dependents in *other* files, chosen so the file under
edit contains no textual hint that callers exist. Prompt is a plain feature request.
Nudge under observation: `api-delta-write.sh`. Question: does an unprompted agent go
look at who calls this?

**T2 — test-verify task (targets the test nudges).** Modify a source file whose test
file is associated **only by import**, never by filename similarity. Prompt is a
plain bug-fix request that never says "test". Nudges under observation:
`test-reminder.sh`, `test-run-note.sh`, `recap-stop.sh`. Question: does an unprompted
agent run the tests that actually cover the change?

**Headroom precondition (zero LLM, mandatory before any session).** For each
(repo, task) pair assert: (a) the nudge actually fires on that edit — by invoking
the hook directly with a synthesized `tool_input`; (b) the target file contains no
in-file hint of the nudged fact — no caller name, no test-file reference. A pair that
fails either assertion is **re-sited or dropped**, never run.

## 4. Frozen metrics

| ID | Metric | How measured |
|---|---|---|
| M1 | Nudge fired | Hook stdout channel present in transcript ∧ `shown` row in `nudge-events.jsonl` |
| M2 | Nudge **truthful** | Adversarial refutation verdict vs. the repo's real code (Phase 4) |
| M3 | Agent acted on it | Deterministic detection: `get_dependents` call naming the symbol (T1), or an observed test run covering the associated test (T2) |
| M4 | Hook latency | Wall time per hook invocation vs. the 5 s `hooks.json` timeout |
| M5 | Tool-doc accuracy | Every field promised in the tool description is present in the actual response, and every field returned is documented |
| M6 | Index fidelity | Per repo: file/chunk counts, dependency-edge count, test-association coverage %, each spot-checked against a hand-verified sample |

**M2 is the headline metric, not M3.** A nudge that fires often and is obeyed often
but is sometimes wrong is a net-negative product. A false nudge is filed HIGH
severity regardless of how helpful the true ones were.

### What this protocol does NOT claim

This is **single-arm observation**. M3 is a rate, not a lift, and it must never be
reported as one. Per the launch rule in the nudge roadmap, the *only* Lien nudge
lift claims that may be published are the ones from the paired-arm A/B v2 (blast
10/10 vs 3/10, verify 10/10 vs 0/10). A paired ON/OFF arm over this corpus is a
legitimate follow-up (roughly double the Phase 3 cost) but is explicitly **out of
scope here** and may not be back-fitted after the fact.

### Abort criteria

- More than two repos fail to index → stop; fix indexing before spending on sessions.
- C2 byte-comparison of saved settings fails → abort the run, report contamination.
- A hook exceeds the 5 s timeout on more than one repo → stop; that is a shipping bug.
- Zero nudges fire across the whole corpus → the plumbing is broken, not the agents;
  stop and debug rather than reporting a behavioral null.

## 5. Phases

Run as **three sequential workflows**, reading results between them, rather than one
mega-run. Phase gates are real: a red gate stops the spend.

### Phase 0 — provision & precondition (deterministic, no LLM trials)

Build the CLI and native parser; clone the corpus at pinned SHAs; assert C1 per
repo; index each repo; record M6. Assert task headroom (§3). Emit a machine-readable
corpus manifest. **Gate:** abort criteria above.

### Phase 1 — MCP tool truth-testing (6 agents, one per tool, foreign repos only)

Each agent drives its tool against three corpus repos and grades M5 plus failure-mode
clarity. Concrete edge matrix per tool: empty and whitespace-only query; single-char
query; unicode; regex-special characters; nonexistent path; directory passed as a
file path; absolute vs. relative path; pagination boundary at `offset == total`;
`depth` supplied on a symbol-level query (documented as depth-1 only); batch call
mixing valid and invalid paths; filters that match nothing. Every finding carries a
verbatim repro.

### Phase 2 — hook plumbing verification (deterministic, zero LLM)

For each of the ten hooks, feed the **real stdin shape** Claude Code sends and assert:

- the documented output channel is the one used — `hookSpecificOutput.additionalContext`
  for the annotators, `updatedInput` for `augment-explore-task.sh`, and
  `{"decision":"block","reason":…}` for `recap-stop.sh`;
- fail-open on garbage, missing fields, empty stdin, and absent `jq`;
- each env kill switch is honored (`LIEN_ANNOTATE_GUARD`, `LIEN_ANNOTATE_MIN_RISK`,
  `LIEN_ANNOTATE_TTL_MIN`, `LIEN_DELTA_HOOK`, `LIEN_TEST_REMINDER`,
  `LIEN_TEST_VERIFY`, `LIEN_BLAST_HOOK`, `LIEN_RECAP`, `LIEN_EXPLORE_INJECT`,
  `LIEN_SUBAGENT_NUDGE`, `LIEN_NUDGE_EVENTS`, `LIEN_STRUCTURAL_RANKING`);
- the habituation guard suppresses the second annotation of the same file and
  respects the risk floor;
- a `session_id` containing path-traversal characters is rejected;
- `recap-stop.sh` honors `stop_hook_active` — a Stop hook that blocks without that
  guard is an infinite loop, so this case is asserted explicitly;
- M4 latency.

### Phase 3 — live nudge trials (the core; 18 headless sessions)

Per (repo, task): one fresh `claude` process, `cwd` = the clone, plugin wired via
`--settings`, ordinary prompt, full transcript captured. Extract M1, M3, M4 and the
`nudge-events.jsonl` rows. **No arm comparison** (§4).

### Phase 4 — adversarial truth audit (fan-out over every nudge that fired)

Independent skeptics, prompted to **refute**, check each fired nudge's claim against
the repo's real code: do those dependents exist, is that risk level defensible, is
that the test file that actually covers this change, did that function really cross
the threshold? Majority-refuted ⇒ M2 fail ⇒ HIGH finding. Per-language, since this is
where the #866–#869 regressions would resurface.

### Phase 5 — cold-start / first-run UX (2 agents)

The plugin advertises **"No per-project setup required."** Test that claim honestly:
no global `lien` on PATH (the default — `lien` is not linked on a fresh machine, as
confirmed while writing this plan), the `npx -y @liendev/lien@latest` resolution
path, cold vs. warm npx latency against the 5 s hook timeout, what the very first
`Read` surfaces before an index exists, multi-repo `cwd` resolution, and the linked-
worktree overlay path.

### Phase 6 — synthesis + first real telemetry read

Merge, dedupe and rank findings; build a per-nudge **trust ledger** (fired / truthful
/ acted-on, per language); read `lien stats --format json` over the corpus indices.
That read doubles as the first substantive look at the telemetry-v2 funnels, which
gates the Cursor port decision.

## 6. Cost

Phases 0, 1, 2 and 5 are cheap: deterministic checks and Claude-subagent work, no
OpenRouter spend at all. Phase 3's eighteen headless `claude` sessions bill against
the Claude subscription, not per-token API credit — this dogfood is **not** a
repeat of the harness-calibration spend pattern. Phase 4 scales with how many nudges
actually fire.

The dominant cost is wall-clock, not money. Nothing here touches
`OPENROUTER_API_KEY`.

**Model policy.** Every dispatched agent runs on **Sonnet** (`args.model`, default
`sonnet`), matching the repo's standing policy of Sonnet for build/probe/verify work
and keeping token pressure off the orchestrating session. The one carve-out the policy
grants Opus is adversarial review, which is exactly what Phase 4 is; it nonetheless
defaults to Sonnet here to keep the run cheap, and is escalated per-run with
`args.auditModel = 'opus'` if a refutation pass comes back unconvincing. Orchestration
stays on the session model.

---

## 7. Do not

- Do not run behavioral trials inside the Lien repo, or in any directory whose
  ancestors carry Lien-aware agent instructions. That is C1, and it invalidates
  every behavioral number.
- Do not add or redefine a metric after trials have run. §4 is frozen.
- Do not convert an M3 rate into a lift claim. Single arm, single arm, single arm.
- Do not report "the agents ignored the nudge" before Phase 2 proves the nudge was
  actually emitted. Silent plumbing looks exactly like a behavioral null.
- Do not quietly drop a repo that failed to index. Quarantine it visibly; a repo
  Lien cannot index *is* a finding.
